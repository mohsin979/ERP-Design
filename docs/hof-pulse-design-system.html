HOF Pulse Design System

One design system for the whole ERP (CRM, People / HRMS, Accounting, Case Management, Petition Studio and Settings), so every module looks and behaves like one product. Every value here comes from the built CRM. Use it as the source of truth when designing or building any module.

FontDM Sans: 400 Regular, 500 Medium, 600 SemiBold, 700 Bold (Google Fonts).
IconsPhosphor Icons, Regular weight only (phosphoricons.com, MIT). Module tiles on the ERP home screen use the hand-drawn module artwork.
Base text size13px for controls and UI text, 14px for table data and primary buttons.
Control height29–32px. Inputs are 8px/10px padding at 13px. Table rows are 36px.
Corner radius8px for every control. Larger surfaces step up: 10 (menus, cards), 12 (modals), 14 (board columns).
AccentOne blue #1869EC for selection and active states. Black #000 for primary actions and the active navigation item.

Principles

Quiet surfaces

White surfaces on a near-white page, hairline greys, almost no shadow. Colour is only for state: selection, status, errors.

Black is the action

A screen has one primary action and it's black. Everything else is a white bordered or text-only control.

Dense, readable data

36px rows, 13–14px text and a grid on both axes, so a lot of records stay scannable.

Same thing, same pattern

A table, filter, modal or record panel works the same in every module. Reuse before creating.

Colour

Use tokens only; never hard-code a new hex value. Brand and neutral tokens are for app chrome and controls; record tokens are for data (tables, record panels, cards).

Brand & neutrals

Record (data) text & lines

Status tones

A tone is a text colour on a tinted background. It appears on pills and on the left accent line of event cards.

Typography

DM Sans throughout. Sizes are deliberately small and close together, and hierarchy comes from weight and colour more than size. Line-height is 1.4 for UI and 1.5 for paragraphs.

Icons

Phosphor Regular, drawn on a 256 grid and filled (no strokes). Sizes: 13–15px in controls and menus, 15px in navigation, 16px in primary buttons, 14px for every chevron. Default colour --hof-gray-600; white on black buttons; blue on blue tiles. The set below is everything the CRM uses. In a new module, pick from Phosphor Regular in the same way.

App shell

Every module uses the same shell: a 200px left navigation (collapsible to 56px), a 45px header over the content (search, then the right-hand icons), and the content area on --hof-page-bg. The ERP home lists the modules as tiles; entering a module shows its shell.

Content & terminology

Do
  • Title Case for buttons, menu items, tabs and view names: "Add Employee", "Save View", "View Settings".
  • Sentence case for descriptions, help text and messages.
  • Dates: Sep 4, 2026; date-time Sep 4, 2026, 10:15 AM. Money: AED 4,000 with thousands separators.
  • Empty values show "—". Placeholder search text is "Find or Ask".
  • Undefined actions open "Not defined yet."
  • Use the shared names: Object, Record, Property, Pipeline, Stage, Owner, Team. A person is one record across modules (Contact → Customer → Employee links, never a copy).
Don't
  • Don't write "Warning". Workflow behaviours are only Required and Automatic.
  • Don't add page titles above record lists; the navigation already says where you are.
  • Don't add explanatory copy the design doesn't call for.
  • Don't use a second accent colour, gradients or heavy shadows in product UI.
  • Don't rename an existing concept in a new module (e.g. "Application" for a Case).

Rules for new modules (People / HRMS and others)

A checklist to design or build any module so it matches the CRM. If a needed pattern isn't here, reuse the closest one, or ask before inventing.

1 · Tokens onlyColours, radii, shadows and spacing come from the tokens below. No new hex values, fonts or radii.
2 · ShellSame 200px navigation (groups + items, active = black) and 45px header. The module name sits at the top of the navigation, with ← back to the ERP home.
3 · Record listsEmployees, Leave requests, Attendance… use the record page: view pills, View Settings / Save View, Table / Board, Export, +, search, Filters, then the 36px table.
4 · RecordsA record opens in the side panel from its underlined name, and expands to the full record with workspace tabs (Overview, Activity, Files…).
5 · Create & editCreate and edit in a 440px modal (fields: label + input); large editors in a right drawer.
6 · StatusStatus is a pill with a tone. Ownership (Owner, Manager, Team) is a separate property, never combined with status.
7 · SettingsSettings pages use the settings header (title, description, one black action) and tables, menus and radio cards from this file.
8 · StatesEvery list has an empty state in the illustration style. Every undefined action opens "Not defined yet." Errors use red text, red borders or a red pill only.
9 · Icons & typePhosphor Regular at the sizes above; DM Sans at the type scale above. No other icon sets or fonts.
